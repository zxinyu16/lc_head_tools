# 信用证辅助制单微信小程序

[产品需求](PRD.md) · [页面设计](design/页面结构与交互说明.md)

## 当前可用

本项目已在微信开发者工具中导入并编译。打开本目录的 `project.config.json`，模拟器默认显示业务总览。

- 新建、搜索、复制、归档多笔本地业务。
- 手动填写交易双方、发票号和日期；修改后重新核对。
- 录入 46/47 场相关编号、固定文字或操作要求，并指定适用单据。
- 按“名称：内容”格式批量整理关键词，再逐条确认范围。
- 粘贴含 SWIFT 场次的信用证文字，提取信用证号、交易方候选和 46/47 场明确标出的 PI/保单编号；逐项核对、选定适用单据后导入。
- 保存和应用字段模板；动态编号不带入新业务，同名规则冲突时不覆盖。
- 发票、装箱单抬头预览；缺失项跳转编辑；生成可编辑 Word 抬头草稿并记录历史版本。
- 从微信会话导入 PDF，或从相册/相机导入图片，仅供本地查看。

## 使用限制

业务资料仅保存在当前微信小程序的本地存储；清理小程序数据会删除它。导入文件也保存在本机。文字提取只支持已复制出的、带场次标记的信用证文本；图片和扫描版 PDF 尚无 OCR，其他未识别要求只展示原文。尚无云端同步、多人权限、正式发票或装箱单版式。Word 文件是抬头草稿，不含货物明细，使用前须人工核对。

开发样本可在 macOS 上用 `python3 scripts/ocr-pdf.py <PDF路径> --output <文字文件路径>` 进行本机 OCR，再把文字粘贴进小程序核对。此工具不上传文件，也尚未集成进小程序运行环境。

项目配置使用本地调试 AppID。要在真机预览或上传体验版，需要由项目所有者换成自己的正式 AppID。此阶段未执行预览上传或发布。

## 开发和验证

安装 Node.js 后执行 `npm test` 和 `npm run check`。修改 `src/domain/documents.mjs` 后执行 `npm run sync:miniprogram`，把共用业务规则同步到小程序。当前测试覆盖条款适用范围、编号缺失、模板动态值清空、冲突阻止、业务复制和 Word 包结构。

下一步需真实脱敏信用证和单据模板，才能设计识别字段映射与正式版式。
